## 🇨🇳 中文

当你需要创建可持续复用的虚拟角色身份，而不是生成一张一次性人像时使用。输入角色简报、人脸参考和服装参考，流程固定三阶段：人脸 → 服装 → 资产表，性格、职业、生活方式、叙事道具、微表情和剪影记忆点都嵌入人脸与服装设计，不额外增加制作阶段。人脸候选每轮生成四张，以四个独立图片卡片展开供你选择，不折叠成一个结果；一旦选定，这张主脸就是后续唯一的人脸依据，服装参考可以提供服装、鞋子、配饰、发型、妆面和可见细节，但不能覆盖已确认的人脸。最终交付是一张一次生成的 16:9 角色资产表，含正面、背面与人脸锚点，并说明其中每个组件的用途。生成失败时保留全部硬性约束、不静默换脸，用更短但语义等价的指令自动重试一次。

- 角色简报 + 人脸参考 + 服装参考 → 一张 16:9 角色资产表
- 每轮四张人脸候选，四个独立卡片展开供挑选，不折叠成一个结果
- 固定三阶段：人脸 → 服装 → 资产表，性格与职业嵌进设计标准
- 交付正面、背面与人脸锚点，并逐项说明资产表各组件的用途
- 人脸锚点同时作为发型与头部轮廓参考，禁止贴边裁掉发型
- 失败不静默换脸：保留硬约束与同一来源，语义等价指令自动重试一次

## 🇬🇧 English

For when you need a durable, reusable virtual character identity rather than a one-off portrait. Feed it a character brief plus face and costume references, and it runs a fixed three-stage order: face, then costume, then asset sheet. Personality, profession, lifestyle, narrative props, micro-expressions and silhouette memory points are folded into the face and costume design instead of adding extra stages. Face candidates come four at a time, presented as four separate image cards rather than one merged result; once chosen, that main face becomes the only basis for everything downstream, and costume references may supply clothing, shoes, accessories, hairstyle, makeup and visible detail but never override the confirmed face. The final delivery is a single-generation 16:9 character asset sheet with front, back and face anchors, each component's purpose explained. On failure it keeps every hard constraint, never silently swaps the face, and auto-retries once with a shorter but semantically equivalent instruction.

### ✨ What it does

- Character brief, face reference and costume reference in, one 16:9 character asset sheet out
- Four face candidates per round shown as four separate cards, never merged into one result
- Fixed three stages — face, costume, asset sheet — with persona folded into the design standards
- Delivers front, back and face anchors with each sheet component's purpose spelled out
- The face anchor doubles as hairstyle and head-silhouette reference, with no edge-cropped hair
- On failure it never silently swaps faces: same source, same hard constraints, one semantic retry
